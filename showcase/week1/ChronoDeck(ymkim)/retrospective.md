# ChronoDeck — 회고

## 스펙 판단
- 넣으려다 뺀 기능: 아이콘 등 시각적 요소로 버튼 UI/UX 개선 — 시간 부족으로 제외
- 빼서 다행인 기능: 상태 관리 주체를 휴대전화로 할지 PC로 할지 명확히 결정하지 못한 채 진행한 점 — 어느 쪽이든 일찍 정했어야 했음
- 넣었는데 후회한 기능: 없음

## 효율 돌아보기
- 이렇게 했으면 더 빨랐을 것: 상태 관리 주체(Phone vs PC)를 스펙 단계에서 확정했으면 전체 구현이 더 매끄러웠을 것
- AI 활용에서 효과적이었던 점: Week 0에서 검증한 Swift 네이티브 앱 + 글래스모피즘 스킬을 그대로 재사용해서 iOS/Watch UI 구현이 빨랐음
- AI 활용에서 비효율적이었던 점: 상태 관리 아키텍처가 확정되지 않은 상태에서 LLM과 함께 헤맴 — 설계 결정을 AI에게 맡기려다 오히려 시간 낭비

## 다음 주에 가져갈 것
- 아무리 단일 레포라도 Watch → PC까지 전체 플랫폼 사이클을 한 주에 다 잡는 건 그만 — 플랫폼당 주차를 분리하거나 범위를 과감하게 줄이기
- 아키텍처 결정(상태 관리 주체, 통신 방식 등)은 코딩 전에 직접 확정하고 LLM에게는 구현만 맡기기
