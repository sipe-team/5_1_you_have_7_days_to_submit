# ChronoDeck 제품화 — 회고

## 스펙 판단
- 넣으려다 뺀 기능: 여러 Mac 관리, 프로필/프리셋 동기화, 인터넷 원격 제어, launch-at-login 고도화
- 빼서 다행인 기능: 여러 Mac 관리 — 이번 주의 병목은 사용자가 한 대의 Mac에 안정적으로 연결하고 설치/업데이트까지 끝내는 제품화 경로였기 때문에, 라우팅과 상태 모델을 늘렸으면 출시 안정성이 떨어졌을 것
- 넣었는데 후회한 기능: 배포/업데이트/심사 대응을 한 주 안에 모두 제품 범위로 끌어안은 것 — Sparkle, DMG, App Store 심사, 개인정보 매니페스트, 로컬라이제이션이 각각 별도 체크리스트라 기능 개발보다 검증 비용이 컸다

## 효율 돌아보기
- 이렇게 했으면 더 빨랐을 것: 먼저 "한 사용자가 설치해서 키 명령을 전달하는데 성공" 이라는 MVP에 적합한 체크리스트를 만들고, 메뉴바 polish나 랜딩 카피는 그 뒤에 붙였으면 더 빨랐을 것
- AI 활용에서 효과적이었던 점: macOS 메뉴바 전환, 키 입력 편집 UI, Sparkle 업데이트 UI, 로컬라이제이션 정리처럼 반복 수정이 많은 작업을 빠르게 밀어붙일 수 있었다. v0로 랜딩 페이지 초안을 만들고 한국어/영어 카피를 다듬은 것도 속도가 좋았다
- AI 활용에서 비효율적이었던 점: 배포 관련 작업은 실제 서명, 번들 ID, App Store Connect, Sparkle feed처럼 로컬 코드만 보고 판단할 수 없는 부분이 많았다.

## 다음 주에 가져갈 것
- 제품화는 체크리스트가 더 중요하다. 설치, 권한, 업데이트, 심사, 다운로드 경로를 알고 있는게 중요했다.
- AI에게 맡길 수 있는 작업과 실제 계정/서명/심사에서만 확인되는 작업을 분리해서 계획한다.
- "완성"의 기준을 코드가 아니라 사용자가 입장에서 생각한다.
