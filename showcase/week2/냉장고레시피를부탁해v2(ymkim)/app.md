# 냉장고 레시피를 부탁해 v2

## 한 줄 소개
> 방송된 레시피를 모아두는 냉장고를 부탁해 팬 사이트 — FastAPI + NextJS 이중 스택을 NextJS 단일 풀스택으로 전환

## 문제 정의
v1은 FastAPI(백엔드)와 NextJS(프론트엔드)로 분리되어 있었으나, 트래픽과 복잡도에 비해 불필요한 아키텍처 분리였다.
또한 데이터 구조를 충분히 설계하지 않은 채 진행해 복잡하게 얽혀 있어 유지보수가 어려웠다.
v2에서는 NextJS 단일 스택으로 전환하고 데이터 구조를 단순화하며, 주간 크롤링 기반 갱신 파이프라인을 구축한다.

## 링크
- 서비스(v1): https://nbrbtk.metts.today/
- 소스코드: https://github.com/

## 기술 스택
| 영역 | 선택 | 선택 이유 |
|------|------|----------|
| 프론트엔드 + 백엔드 | Next.js (풀스택) | FastAPI 분리 불필요, API Routes + SSR로 단일 레포 통합 |
| 데이터 구조 | 단순 재설계 | v1 복잡도 원인 제거, 레시피 중심 평면 구조 |
| 갱신 파이프라인 | 크롤링 (주 1회) | 방송 정보 자동 수집으로 수동 업데이트 제거 |
| 배포 | Vercel | 파이프라인 전환과 함께 배포 자동화 |
| AI 활용 | LLM 기반 데이터 정형화 | 정형화된 레시피 사이트가 없어 비정형 소스를 LLM으로 파싱하여 정형 데이터로 변환 |
