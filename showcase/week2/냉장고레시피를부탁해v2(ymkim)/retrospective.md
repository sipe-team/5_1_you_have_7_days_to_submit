# 냉장고 레시피를 부탁해 v2 — 회고

## 스펙 판단
- 넣으려다 뺀 기능: 관리자 UI, 검색 고도화, 즐겨찾기/로그인
- 빼서 다행인 기능: 관리자 UI — 이번 주의 핵심은 기존 FastAPI + NextJS 구조를 단순화하고 데이터 파이프라인을 다시 잡는 것이었기 때문에, 관리 화면까지 넣으면 문제 범위가 너무 커졌을 것
- 넣었는데 후회한 기능: 정형적인 데이터 소스 없이 LLM 기반 레시피 데이터를 만들려고 한 것— 방송/웹 문서에서 뽑아낸 데이터가 생각보다 일관되지 않았고, 같은 입력에서도 재료/조리순서/출연자 정보가 안정적으로 나오지 않아 운영 데이터로 바로 쓰기 어려웠다

## 효율 돌아보기
- 이렇게 했으면 더 빨랐을 것: 먼저 사람이 검수 가능한 최소 스키마와 샘플 데이터셋을 만들던지, 내가 TV를 보면서 데이터를 만들고, LLM은 그 스키마를 채우는 보조 역할로 제한했어야 했다
- AI 활용에서 효과적이었던 점: 기존 구조를 읽고 NextJS 단일 스택으로 전환할 범위를 잡는 데는 도움이 됐다. 불필요하게 분리된 API와 프론트엔드 흐름을 하나의 배포 단위로 정리하는 판단은 엄청나게 빨라졌다
- AI 활용에서 비효율적이었던 점: LLM에게 비정형 레시피 데이터를 바로 정형 데이터로 만들게 했더니 결과 품질을 예측하기 어려웠다. 데이터가 틀렸을 때 원본 문제인지, 프롬프트 문제인지, 스키마 문제인지 분리해서 확인하기 어려웠고 해결도 못했다
