## 효율 돌아보기
- 이렇게 했으면 더 빨랐을 것: '전체 작업 플로우' 를 정해서 내가 어떻게 쓰고싶언지 먼저 정의했어야 함. LLM의 도움을 받는것은 좋지만 일단 인터페이스 자체를 기능으로 구현해야 추후 MCP/Plugin 형태로 내보내기 좋음
- Week 2에서 가져온 점: 비정형 데이터를 최대한 배제하고, Remember, Wanted 별 파서를 사용해 공통된 데이터로 만들어내었다.
- AI 활용에서 효과적이었던 점: 크롤러 구현 - playwright 로 브라우저 열어주고 열심히 만들어보라고 하면 잘 만듦, OpenClaw tool 정의 - openclaw의 llm.txt 주소에서 직접 스펙을 확인하고 잘 만듦. 특히 `resumaker_search_applications`, `resumaker_update_application_status`, `resumaker_append_application_note`처럼 도구를 어떻게 구현할지 상의하고 만드니 openclaw가 바로 적응하고 도구를 사용했음.
- AI 활용에서 비효율적이었던 점: 만약 브라우저를 돌려서 데이터를 획득하라고 했으면 비효율적이었을듯
